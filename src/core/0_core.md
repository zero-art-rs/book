# Core

0-ART is a tree-based Continuous Group Key Agreement (CGKA) protocol, which is a modification of the existing ART, TreeKEM and MLS protocols. This protocol manages to combine their strengths.

Core is a main library of `zero-art` asynchronous verifiable group management protocol. It encapsulates the following crates:
- [cortado](https://github.com/zero-art-rs/core/blob/main/cortado) - carefully crafted elliptic curve defined over [bulletproofs](https://crates.io/crates/bulletproofs)' ristretto scalar field (e.g. 'native elliptic curve' for [bulletproofs](https://crates.io/crates/bulletproofs)).
- [zrt-zk](https://github.com/zero-art-rs/core/blob/main/zk) - zero-knowledge proofs for ART trees based on [bulletproofs](https://crates.io/crates/bulletproofs).
- [zrt-art](https://github.com/zero-art-rs/core/blob/main/art) - different ART trees routines.
- [zrt-crypto](https://github.com/zero-art-rs/core/blob/main/crypto) - various cryptographic primitives (X3DH etc.).

ART tree, in it's nature, is a binary tree, which consists of leaves and internal nodes. Both of the types store some data. The main part is `public_key`. For a leaf it is the public key of some user in a group. On the other hand, internal node contain `public_key`, which corresponds to the secret key of the Diffie-Hellman key exchange between its two children nodes. Computed secret is a point, but we can derive a scalar secret from it. For example, we can take an x coordinate of a resulting point. In this way, having any leaf secret and existing tree, it is possible to recompute the secret in a root node of the tree. The knowledge of the root secret allows to derive encryption key from it for further message encryption. With derived in such way secret anyone in a group will be able to decrypt it. Common operations with ART are implemented int the [zrt-art](https://github.com/zero-art-rs/core) crate. This crate provides methods for leaf key update, new member addition  or member removal, etc.  More details on them can be found [here](./1_core.md). 

Each of the art update is baked up by the zero-knowledge proof based on [bulletproofs](https://crates.io/crates/bulletproofs). Note, that if secret key and corresponding public key of some leaf changes, then their parent node secret key also changes. For that reason, leaf update will cause the update of the whole path from the leaf to the root. With our proofs, one can prove that the leaf and all the leading nodes are updated correctly. There is also a proof of common secret, computed with Diffie-Hellman key exchange, being computed correctly for every level of a tree. More details about it are on the [proofs](3_core.md) page.
